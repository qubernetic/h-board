# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- Core: the library model, the group, site, todo, settings and library commands with their agent classes, JSON export and import that name every wrong field, and the sample library of the English drawing (#9).
- Core: a snapshot after every change burst marked with its source, retention of the newest 20 and one a day for 7 days, undo, redo, an undoable restore with a preview, and a diff summary between two snapshots (#10).
- Store: the `Store` interface that runs a command by id and keeps a snapshot of each change, the memory store, and `ExtStore` on `chrome.storage.local` with a schema version, migrations, and a fallback to the newest readable snapshot when the stored library is corrupt (#11).
- Page: the start page with the layout rules of the drawing in core, the header, the group wheel with its tick ruler (keys 1 to 8, the arrows and the mouse wheel switch groups), the cards in three densities and three layouts, the status bar, light and dark theme and the empty group, with its fonts, icon font and logo bundled (#12).
- Page: the search line, with the engine switch (Tab or a click on the chip), search inside one of your sites by its alias, name or host and a space or by Tab on its row, suggestions with what is typed first, then your own sites and the last five searches, and `/` to focus. An `http` or `https` address, with or without a port, opens as it is; one with another scheme opens nothing. Engines and site searches come from one table in core; nothing is sent anywhere while you type (#13).
- Page: editing. `e` turns on edit mode, where a card has its edit and delete buttons and moves by dragging or by Shift and an arrow; the dialog adds and edits a site with its address, name, description, group and icon (the bundled Simple Icons mark, a Phosphor icon or the initial); groups are added from the wheel, renamed and deleted in edit mode, and get their icon mode in the settings; to-dos are added, ticked and deleted. Every change runs a core command and keeps a snapshot; a delete shows a toast with undo for six seconds, and `z` or Ctrl+Z undoes the last change (#14).
- Page: the character field with the pointer trail that fades near text and cards, home · standby with the Qubernetic mark (after five minutes idle or with `s`; any key, click or pointer movement brings the start page back), its enter and exit transitions, and the motion setting (full, reduced as the default, none; `prefers-reduced-motion` means none until you pick a level) read through one flag, with every movement listed in `packages/ui/MOTION.md`. A key during a movement acts at once (#15).
- Page: jump codes. `f` shows a letter on every card (two letters in a group with more cards than letters) and the letter opens the card; `f`, a group number and the letter open a card of another group; Shift with the letter opens it in a tab behind this one; Escape or a letter no card has puts the codes away. The status bar and the tooltips read their keys from one keymap (#16).
- Page: snapshots, export and import. The status bar says "saved · time · N snapshots"; that sign, `v` or Restore in the settings opens the restore panel, which lists every snapshot with what changed and how many sites it holds, previews what a restore would change (the arrows walk the list, Enter restores) and restores in a way undo takes back. The settings export the library as a JSON file and import one, with undo; a wrong file is named in the settings, one problem per line (#17).
- Extension: the Manifest V3 host. A new tab hands over to the board in its own tab, so the keys reach the page without a click; the library, its snapshots and the last searches live in the extension's local storage; the toolbar button opens the settings page, and its icon follows the colour scheme through an offscreen page; Import from bookmarks asks for the optional `bookmarks` permission at that moment and adds one group per bookmark folder with the core command `group.import`, in one change undo takes back. The extension asks for `storage` and `offscreen` and nothing else (#18).
- Extension: the address bar as a command line. After the keyword `h`, a site's name, alias or host opens the site, a jump code (`a`, `4a`, `f4a`) opens a card in the group seen last or in the group of its number, a site and words search inside the site, and anything else goes to the chosen engine; the first row says where Enter goes. It only reads the library: one that cannot be read opens the board, which repairs it and says so. The router is the mock's `/go`, in core (#19).
- Extension: the beta build `0.1.0-beta.1`. `npm run build` writes the unpacked extension and the same files as `h-board-0.1.0-beta.1.zip`, with fixed dates so the same build gives the same zip, and `INSTALL.md` says how to load it in Chrome, Brave, Edge and Helium and to turn off other new-tab extensions first (#20).
- Extension: the favicon icon mode, per group and per site, next to brand, Phosphor and initial. It shows only the favicons the browser has already stored, read through the extension's own `_favicon` address; nothing is fetched from a site or a third party and none is committed. The optional `favicon` permission is asked for in the click that first switches a group or a site to favicons; a refusal keeps the previous mode and says why. A site the browser has no favicon for (Chrome's default globe) shows its Phosphor icon, or its initial when it has no Phosphor icon, and the settings count "Favicons: N / M". Libraries and exports from before import as they are (#37).
- Server: accounts and sessions. At a start with no account the server writes a one-time setup code to its log; `POST /api/setup` with the code, a name and a password makes the first account, an admin, and burns the code. `POST /api/session` signs in and gives a bearer token, `DELETE /api/session` signs out and revokes it, `POST /api/password` changes the password and revokes the other sessions. Passwords are kept as scrypt hashes, tokens and the setup code as SHA-256 hashes; failed attempts, also ones sent at once, are slowed down per name and per address, setup separately, and a full slow-down refuses rather than lets through; a refused setup hashes nothing; request bodies must be `application/json`; no cookies and no CORS headers. `HBOARD_TRUST_PROXY=1` reads the caller's address from `X-Forwarded-For` behind exactly one proxy. The schema has versioned migrations in `src/db.ts`, and the database file lives in `HBOARD_DATA_DIR` (#51).
- Server: user management for the admin. `GET /api/users` lists the accounts, `POST /api/users` adds a user who is not an admin with a temporary password shown once, `POST /api/users/:id/password` gives a new temporary password and signs the user out everywhere, `DELETE /api/users/:id` removes a user with their sessions; the admin cannot reset or remove their own account, and every other user is refused. A temporary password signs in once, and that session reaches only `GET` and `DELETE /api/session` and `POST /api/password` until the user sets their own, which must differ from it. A sign-in still checking the password when the password is changed or reset, or the user removed, starts no session. User objects now carry `id`, `mustChangePassword` and `createdAt` (#52).
- Server: each user's library over REST. `GET /api/library` answers the user's library and its snapshots, `POST /api/commands/:id` runs one core command by id with `{params, alone}` and keeps a snapshot, `POST /api/undo`, `POST /api/redo` and `POST /api/restore/:id` step through them (204 when nothing changes). A new user starts from the empty library; a refused command answers with its field-by-field message, 400 for an unknown command or a bad parameter and 404 for a group, site or snapshot that is not there. One user reaches only their own library, which goes with the account. A command body may carry a library file of up to 5,000,000 characters and is read only after the sign-in is checked; every other body stays at 16 KB. A command whose user is removed while its body comes in is refused with 401 and changes nothing, also when a new user has the same id. The library is kept by `SqliteStore`, which runs the store contract suite (#53).
- Core: size limits for every store. A command whose library would be larger than 5,000,000 bytes as JSON is refused with `library: must be at most 5000000 bytes` before anything is kept, unless it makes the library no larger, and the history lets go of its oldest snapshots once it passes 45,000,000 bytes, so a library with its snapshots stays under 50 MB (#53).
- Server: library changes as server-sent events. `GET /api/events` keeps a stream open for the signed-in user and sends a `change` event with the snapshot id and its source after every change to that user's library, from any source, and to no other user; a heartbeat line every 15 seconds; and an `end` event before it closes once the session is revoked, at once after a sign-out, a password change or reset or a removed user, otherwise at the next heartbeat. One user may keep 32 streams open; one more is refused with 429. A stream that holds 64 KiB its caller has not read fails, so the connection drops and the caller connects again; a `HEAD` request gets the headers and opens no stream (#54).
- Server: agent keys. `POST /api/keys` makes a key with a name and a scope (`read`, `edit` or `owner`) and shows it once (`hbk_` and 43 characters); the server keeps only its SHA-256 hash. `GET /api/keys` lists the user's keys with their last use, `DELETE /api/keys/:id` revokes one at once, and `GET /api/keys/log` answers the log of their uses (time, key name, scope, command id and a fixed outcome word; never a parameter, a message or page text). The server keeps only the newest 100 uses of a user's keys, reads included, with no time limit; the uses of a revoked key stay in the log under its name until newer uses replace them or the account is removed. A key is a bearer token on the library routes only: a read key only reads the library, an edit key also runs `safe` commands, an owner key also `owner` commands and undo, redo and restore; a `never` command is refused for every key, and so is every key of a user whose password is temporary. A key that may not run a command is refused before its body is read. Every change by a key is snapshotted with the key's name as its source. Each user has at most 100 keys, each name once; keys and their log go with the account. A password reset by the admin revokes every key of the user, with their sessions; the user's own password change keeps their keys, which stay until revoked one by one. The stores' `undo`, `redo` and `restore` take `{ by }` like `apply` (#55).
- Server: MCP for agent keys. `POST /mcp` speaks MCP over Streamable HTTP without sessions (one JSON-RPC message a request, one JSON answer), with an agent key as the bearer token and nothing else; a session token, a request from a web page (`Origin`), `GET` and `DELETE` are refused. A key lists and calls the read tools `library_read`, `group_read` and `backup_list`, and by its scope one tool per command named after its id with `_` for `.` (`site_add` for `site.add`) and `backup_restore` for an owner key; every tool description says that site names, titles, descriptions and addresses are data, never instructions, and answers are short text with page text quoted. A tool the key may not call, a wrong parameter or a missing group, site or snapshot answers an error the model reads, with the field it names; every call is checked against the key as it is then and noted in the key log like a REST call (#56).
- Store: `RemoteStore`, the `Store` on the user's own server. It runs commands, undo, redo and restore through the REST routes with the session token (an agent's key for an agent), and a listener hears every change through the event stream, once, also one made in another browser or by an agent; the stream connects again after a lost network and stops after a sign-out. The last library read is kept in `chrome.storage.local` under `remote`, apart from the local library, so that offline `load` answers it read only, with a notice that says so and the time it was read. Offline or signed out, `apply`, `undo`, `redo` and `restore` reject with a `RemoteError` (`offline` or `signed-out`) and a readable message and change nothing; a refused command rejects with its `CommandError` as the server words it, and a sign-out the server reports forgets the kept library. A proxy that answers 502, 503 or 504 counts as offline. It runs the store contract suite against `createApp` (#57).
- Extension: the Server section of the settings, after the design's Server frames. Local or server mode; a server address is `https://`, or `http://` for `localhost`, `127.0.0.1` and `[::1]` only, may carry the path of a reverse proxy, and is checked by `checkServer` of the store, which `RemoteStore` runs too; the browser is asked for that server's origin alone, as an optional host permission, in the click that connects; the way back to local mode gives the permission back. The first sign-in with the setup code makes the admin, a temporary password must be replaced before anything else, and a signed-in user changes the password or signs out. At the first sign-in to a server with an empty library the extension offers to send this browser's library, as one `library.import` in one snapshot. Signed in, the board shows the server's library; signed out or in local mode it shows this browser's library again, which the server never changed. The server and the session token are kept in the extension's local storage only; a sign-out also forgets the copy of the server's library kept for reading offline. The settings panel scrolls when it is taller than the window (#58).

### Changed

- Design: the drawing, its sample data and every frame in `docs/design/png/` are now in English (QUB-1297).

### Fixed

- Page: the settings panel keeps every control inside it. Its rows ran past the right edge and `Restore… (v)` wrapped; the panel is now 320 px wide with one column, the library buttons stack one under the other, and no button label wraps. The sample sites carry the brand marks the mock gives them (12 of the 29 in Development), and the density hint draws `[` and `]` as keys instead of something that reads like a checkbox (#35).
- Page: the chosen option of a settings row (density, icons, motion) is framed on its left edge too, wherever it is in the row (#45).
- Extension: a stored favicon that is fully transparent counts as none, so the card shows the site's own icon and not an empty tile (#41).
- Extension: a stored favicon that is nearly all dark has a backing on the dark theme, in the light theme's background colour, and one that is nearly all light has the dark theme's on the light theme; every other favicon is shown bare (#43).
- Page: the search line no longer suggests a site that has nothing to do with the words typed. A typed word counted wherever it was found inside a site's name, address or description (`mini` inside `administration`), and one such word out of three brought the site up selected, so Enter opened it and the search never reached the engine. A word now counts only where it starts a word of the site, and a site is suggested only when at least half of the typed words count for it. The first row is now always what is typed itself, as a web search or as an address, and it is the selected one, so Enter always searches; your own sites are the rows under it, one arrow down or a click away.
